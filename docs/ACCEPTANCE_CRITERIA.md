# Acceptance Criteria

## Authentication
- **AC-001:** A valid user can sign in and reach protected pages.
- **AC-002:** Invalid credentials return a generic error and do not reveal whether an account exists.
- **AC-003:** Protected API calls without valid authentication return 401.
- **AC-004:** One user's trial cannot be read or modified by another user.
- **AC-005:** Passwords are stored only as secure hashes.

## Trial management
- **AC-010:** An authenticated user can create and list their own trials.
- **AC-011:** Duplicate trial codes for the same owner are rejected with a clear conflict message.
- **AC-012:** Invalid dates, including end date before start date, are rejected.

## CSV import
- **AC-020:** A valid CSV can be previewed before import.
- **AC-021:** Missing required columns, unsupported statuses, malformed dates, negative visit counts, and duplicate participant codes are reported clearly.
- **AC-022:** Upload size and row count limits are enforced server-side.
- **AC-023:** Import requires explicit confirmation.
- **AC-024:** Failed import does not leave unintended partial participant records.
- **AC-025:** No participant names or other direct identifiers are required by the schema.

## Metrics and charts
- **AC-030:** For a fixture with 120 participants (95 completed, 15 withdrawn, 10 active), total equals 120 and rates are 79.17%, 12.50%, and 8.33% respectively, subject to normal rounding.
- **AC-031:** Counts are computed by backend code, not generated by AI.
- **AC-032:** Empty trials show an empty state and do not divide by zero.
- **AC-033:** If status categories do not reconcile, the UI surfaces a data-quality warning.
- **AC-034:** Chart labels and text summaries make the status breakdown understandable without color alone.

## AI
- **AC-040:** The AI endpoint sends only aggregate metrics and approved aggregate trends to Gemini.
- **AC-041:** If Gemini is not configured or unavailable, the dashboard and metrics still work.
- **AC-042:** AI output is visibly labeled as generated and requiring human review.
- **AC-043:** The system does not invent a follow-up flag or completion date unsupported by the source data and a documented rule.
- **AC-044:** Provider errors do not expose API keys, prompts with sensitive data, or stack traces.

## PDF
- **AC-050:** Authenticated authorized users can download a valid PDF for a trial.
- **AC-051:** PDF metric values match the metrics endpoint for the same snapshot.
- **AC-052:** PDF includes trial identifier, generation time, metric definitions, and appropriate limitations.
- **AC-053:** AI text, if included, is labeled as AI-generated and advisory.

## Audit and operations
- **AC-060:** Trial creation, import, AI request outcome, report export, and login outcomes are logged according to the approved event policy.
- **AC-061:** Audit logs contain no passwords, tokens, API keys, raw CSV rows, or unnecessary participant data.
- **AC-062:** Audit access is authorized and scoped.
- **AC-063:** `/health` returns a simple health response without secrets.
- **AC-064:** Fresh setup follows the README and database migrations run successfully.
- **AC-065:** Tests and type/lint checks are executed and their actual results are reported.
